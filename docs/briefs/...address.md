# Page not found

Route: `/[...address]`
Design: Tools 1h.
Who reaches it: any signed-in user who opens an address no other screen answers — a mistyped
or outdated link, an address cut short, an old bookmark. Anyone signed out is sent to sign in
first and comes back here, as from any screen.
Which width comes first: the desk's, as every screen on the Equipment & Tools axis draws it;
the phone draws the same heading and the same way to the list.

## What it answers

That the address names nothing. **It is 1h's page-not-found view**, drawn in the app's frame
with the rail, the same view a kind's address that no catalog row carries reaches. **The rail
marks no section**, since the address belongs to none — the rule the rail follows (0m).

**It catches only what no route takes.** Every screen that exists answers its own address
first; this is reached only by an address that matches none of them.

## What it always carries

**heading.** `ASSET_LIST_COPY.pageNotFound`. It names the page rather than an item, since the
address carries nothing a reader can read back.

**action.** `ASSET_LIST_COPY.goToTools`, leading to the list. A way to the list rather than
back to it: a reader arrives here from a link or a bookmark, not from the list.

Nothing else: no sentence naming the address, no search, no list of suggestions.

**What it reads:** the reader's session and nothing else, 1 operation.

## What it carries only sometimes

Nothing. Every unknown address reaches the same view, signed-in readers of every kind alike.

## What must agree elsewhere

**One view for every address that names nothing on this axis.** A kind's address with a record
id no catalog row carries (`asset-categories-categoryRecordId.md`) draws exactly this, from the
same component, so the two cannot drift apart. Its rail marks Equipment & Tools: no frame draws
a kind's address that names nothing, so the app decided it by the rule the rail follows (0m),
which marks the section a page belongs to — and a kind's address belongs to Equipment & Tools,
as an item's own does where 1h draws the item's not-found view with the section marked. An
item's own address with a code no item carries keeps `ASSET_COPY.notFoundHeading` and its
sentence, because that address names a code a reader can check against a label
(`assets-assetId.md`).

**The words are the item screens' words**: `ASSET_LIST_COPY.goToTools` is `ASSET_COPY.goToTools`,
the item page's way to the list.
