# Naming — the reasoning

Governs `lib/airtable/**` (with `airtable-access.md`), and any renaming of a field, a screen word or an identifier. **Read this before editing there** — CLAUDE.md carries only the rules that bind code outside this area; the derivation, the evidence and the alternatives weighed are here.

Moved verbatim out of CLAUDE.md — nothing in this file was rewritten. The migration was audited line by line and the result is in the pull request that created this file.

### Screen words and the fields behind them

**A screen word is not a field name, and this table exists so nobody searches the base for one and concludes it is missing.** Three relationships appear here and they are not the same kind of thing: a word that maps to one field, a word that deliberately differs from the field it reads, and a word that is no field at all. Where the relationship is not 1:1 the row says so rather than picking the closest field.

**A CODE IDENTIFIER that diverges on purpose belongs here too (#181), not only a screen word** — the last row is one, and the reason is the same: someone reads `resolveOriginalPOItem`, searches the base for "original", and finds nothing.

**A ROW LEFT THIS TABLE IN #274 AND THE DELETION IS THE FINDING.** It read `` `Billed` (invoice detail box) `` → `PO Items."Invoiced Qty"`, and its reason was that "on an invoice screen `Invoiced` would read as `this invoice`" — which made it the ONE recorded argument against spelling this act `invoiced`. **There is no such screen.** #232 scoped that figure to the invoice being read and deleted the `Ordered · Billed · Delivered` line with the caption under it; nothing in `app/` or `lib/` renders the word today. So the row was not a divergence to weigh, it was a divergence that had already gone, and #274 removed it rather than arguing with it. The distinction it was really about — one document's figure against the ordered item's total — is a `_shared.md` entry and stays there, where it is about two screens rather than two words.

**Divergences that are deliberate rather than drift**, recorded here because the audit that found them is now #181's and this table is where the reasoning belongs: `Amount` is a live formula on PR/Invoice Items and a static currency on PO Items (same meaning, frozen versus live); `Status` names five different value sets on five tables and is unambiguous within each; `Remark` is free text on PR Items and a discrepancy note on Invoice Items. None is a candidate for renaming.

**The rule #181 applied, so the next name has one to follow: a subtraction is named for what it subtracts.** `Outstanding` and `Remaining` were two words for one subtraction and one of them was also doing duty for a second, so three surfaces read as three quantities when there are two. Naming each for its subtrahend collapses them correctly — `uninvoiced` on `Materials` and on the PO detail (same subtraction, two scopes, one word, exactly as `Invoiced Qty` already spans both), `undelivered` on the delivery side. It also PINS THE NAME TO THE ARITHMETIC: if #20 changes `Materials."Uninvoiced Qty"` to subtract delivered quantity, the field has to be renamed in the same edit. That is the point rather than a cost, and it does not pre-empt #20's decision about what "outstanding" should mean — it frees the word by stopping a field from claiming it.

**A FILE NAME IS THE SAME DRIFT ONE LEVEL UP, and the test that kept #181 out of #184's way was "does the name make a claim the contents contradict".** Narrow is not the same as wrong. Two files failed it and were renamed. The old names are spelled here without backticks, because a later sweep for either string must leave this paragraph alone: app/components/DeliveryChips.js → `DeliveryStatusMarks.js`, because the marker beside the chips is documented at length as deliberately NOT one (`InferredMarker` then, `QualifierMarker` since #210 — see below); and scripts/tests/offline/guard-placement.mjs → `source-shape.mjs`, because its own exported `title` had already moved to `Call-site shape` and half of what it holds — `Quotations.File` has one writer, `Packing List File` has exactly two — is a writer count rather than a guard, in the category this file is named as the home of. Two were considered and left, with the reasons, because "rename it" is not the fix: `lib/materialsCache.js` describes two of its three writes (the third, `PO Items.Material`, is a link and not a cache), but whether that write belongs in a cache module at all is #184's question; and `lib/overagePR.js` also writes an invoice line and a delivery row, yet the whole correction hangs off that PR — it is even the field name on `Delivery Items` — so the name states the subject rather than one write.

**#210 RAN THAT SAME TEST ON AN EXPORT AND RENAMED IT: `InferredMarker` → `QualifierMarker`.** The component is a `!` in a circle whose whole meaning is the sentence handed to it, and it carried exactly one meaning while there was exactly one qualifier in the app. #210 removed the invoice axis's inference and put a MISMATCH label through the same component, while #167's overage attribution kept an `inferred` one — so the old name would have been false at one of its two call sites the moment it was reused. It is named for its shape now and the label says what it means, which is what `StatusChip` beside it already does. The test is #181's unchanged: does the name make a claim the contents contradict.

**THE RULE THAT DECIDES WHICH WORD WINS, STATED BECAUSE FOUR SWEEPS HAD TO FIND IT FOUR TIMES (#269).** `line`, `shipment`, `arrival`, `bill` — each was noticed the same way, by somebody reading a screen that said two things for one fact, long after the word had spread. Everything written down before this was the outcome of one of those: a list of words already found wrong, which cannot make a fifth word wrong until somebody adds it. **A concept with an Airtable table behind it takes that table's name, and nothing else may borrow the word.** `Deliveries` is a table, so a `Deliveries` row is a delivery and neither a delivery nor a delivery; `Invoices` is a table, so it is an invoice and not an invoice — the ground #235 stood on when it took a chip from `Billed` to `Invoiced`; `Lines` is a table, so `line` is spent and a `PO Items` row is an ordered item. CLAUDE.md carries the rule because that file is read at the start of every session and this one is read when the index points at it, and the whole failure this fixes is a word being picked up off the screen instead of out of a convention nobody opened.

- **THE TABLE NAME IS THE TIEBREAKER, NOT THE VOCABULARY, and confusing the two is the reading to guard against.** It settles which of two competing words owns a concept; it does not dictate the prose word for a row. `PO Items` is the table and `ordered item` is the word, because no table owns `ordered` or `item` and the screens chose one — so the table's own name appears in prose only as a backticked reference to the table or to a row of it. **Where no table owns the word, the chosen one is a row in the table above.** That is the layer, and it is what makes this a rule rather than a lookup: the table decides what a word may NOT be spent on, and the word-to-field table decides what it IS.
- **THE VERB SURVIVES ONLY WHERE NO VERB IS ALREADY SETTLED FOR THE SAME ACT (#227).** The clause below frees a verb from the table that owns its noun; this one says when that freedom is already spent. `arrive` does not keep it: #166 chose `delivered` for the same act, so `arrived` is not a free verb but a second one, which is the whole defect. The test is the reason the four words needed four different treatments rather than one, and it is what a fifth word should be held to first. **This bullet said `bill` kept it, on the ground that `Invoices` gives no verb and nothing else claims the act — and the second half was already false when it was written (#274).** `Invoiced Qty` and `Uninvoiced Items` claim it on the base, `uninvoicedQty` in `lib/poItemQty.js` claims it in code, and #235 moved a chip from `Billed` to `Invoiced`. Reading the test correctly therefore sends `bill` the way it sent `arrive`, and the mistake was not in the test but in looking only for another VERB: what settles an act is any derivation already built on the table's name, whether or not it is spelled as a verb.
- **WHICH LEAVES TWO FORMS AND NO THIRD (#274).** Where the act is a PARTICIPLE or a quantity it is `invoiced`, because that is what the base spells; where it is TRANSITIVE — an invoice doing something to an order, an ordered item or an item — it is `charges`. Neither is new: the first is `Invoiced Qty` and every chip on the invoicing axis, the second was already on a screen as `No invoice charges this order yet.` and pinned by `offline/screen-briefs.mjs`. **`invoices` as a transitive verb is barred**, and this is the rare vocabulary rule with a demonstration rather than an argument behind it: #227 rewrote `each bill ordered items` to `each invoice ordered items` and `both bill an ordered item` to `both invoice an ordered item`, and both garden-path into a noun phrase — they shipped and were read that way for two issues before #274 replaced them.
- **A WORD POINTING OUTSIDE THIS BASE KEEPS IT (#227),** the same carve-out CLAUDE.md's US-English rule already makes for a value that belongs to something else. `shipment` is barred for a `Deliveries` row and correct for the commercial act of a vendor shipping in parts — `lib/airtable/invoices.js` says `partial shipments` and `emailed at shipment`, `app/deliveries/[deliveryId]/actions.js` says the vendor emails the invoice at shipment, and all three name what the vendor did rather than what this app recorded. Likewise `arrives` for a request, a query result or a PR. Three sites, named here because the sweep that left them has to be readable as a decision rather than as an omission.
- **`correction` NAMES WHAT A SIGNING CHAIN SENDS BACK, AND THE SECOND CLAIMANT WAS THE OVERAGE (#272).** `Correction Requests` is a table, so a correction is a row of it: one signer returning a request to someone earlier. #167 spent the same word on the request raised for an over-delivery, which is a second REQUEST — the two met on `/prs`, where an `Overage` chip on a row in the list was about to sit under a strip telling the reader to raise a correction. The table wins, and the overage side takes **an overage request** and **an overage order**, which is what the base already spells (`Overage PR`, `Former PO Item`) and what `lib/overage.js` and `lib/overagePR.js` are already named for. **The boundary is what the word is attached to rather than the sense of the sentence:** what a person raises AS A REQUEST may not be called a correction, because that collides with a table; what a person does to a RECORD may, because no table owns that — deleting and re-entering a delivery is a correction to the record, `/deliveries/[deliveryId]/edit` and `/invoices/[invoiceId]/edit` are correction screens, and deletion is the only correction mechanism a delivery has. The sweep took every screen string, three identifiers (`awaitsOverageRequest`, `getOveragesAwaitingRequest`, `OverageStrip`) and the comments in the modules that own the feature; what it deliberately left is prose in files whose subject is elsewhere — no screen copy and no identifier among it — for the next pass over the vocabulary to carry.
- **THE RECORD IS NOT THE ACT, AND THIS IS THE CLAUSE THE TABLE NAMES CANNOT SUPPLY.** A table gives a noun and never a verb, so what an invoice DOES has to be decided somewhere else — and the mistake this bullet made was concluding that nothing had decided it. **A derivation already built on the table's name IS that decision** — a clause #274 put in CLAUDE.md and the routing pass after #263 moved here, since the rule a writer needs there is which word wins, and this is why. Measured at #227: of 422 strings in `*_COPY` constants under `app/` and `lib/`, 27 carried `bill` or `bills` and 6 carried `billed` or `billing`. Measured at #274: 23 of 446, and 0 after the sweep, which is what let the bare word join the copy ban.
- **SO THE FOUR WORDS ARE NOT FOUR OF A KIND, AND THAT DECIDES WHAT A CHECK CAN HOLD.** `shipment` collides with nothing a screen shows, so the bare word is barrable. `line` collides with a line of text, a line number and `Line Label`, so only qualified phrases are. `arrival` and `arrived` are barrable in copy and sit in fifty-one identifiers as well. **`bill` was said to be barrable NOWHERE**, because no expression separates the noun from the verb — true, and it stopped mattering once the verb had somewhere to go (#274): the whole word is barred in COPY and nowhere else, exactly like `arrival`. What survives of that reasoning is prose, where three classes keep the word — Airtable's own billing, `Bill To:` on a vendor's document, and a citation of a word this repo rejected — and where a phrase list would buy the exemption list `line-vocabulary.mjs` has none of. The other reason a check cannot carry the rule stands unchanged: `orderedItemStatus` is one token and no word boundary will ever see it.
- **IDENTIFIERS ARE BOUND, AND #227 RENAMED THEM.** Exempting them would leave the mechanism intact — the identifier is what teaches the wrong word to the next comment written beside it — so the rule reaches them as well as the prose. **This bullet said the rename belonged to #184 and that was wrong twice over:** that issue is about the boundaries between `lib/` modules and never claimed a word, and #227's own body took the identifiers. Corrected here per #181 rather than filed. What #227's measurement really showed was the ORDER, not the owner: `plan.rows[].line` is a data shape rather than a name, agreed by convention and declared nowhere, so it moves writer-to-seed in one edit with a cross-module pin behind it, ahead of any name that only one module reads.
- **WHAT THIS ISSUE DELIBERATELY DID NOT DO, so the next reader does not measure it again.** It swept all 24 open issue titles and bodies: 32 uses, of which five are wrong and are corrected in the tracker rather than in this repository, while every other use is a line of text, a `Lines` row, a query result arriving, or the word quoted as its own subject — a document about a word must not be edited for containing it. Nothing waits on #227 there, since no open issue body quotes a function signature. It widened no check and added no word to a ban list; both were measured and both reasons were in `offline/line-vocabulary.mjs`'s header, where a constraint on editing that file belongs. **#227 then did both**, so that header now records the widening rather than the case against it — see the bullet below for what changed and why the measurement did not have to be redone.
- **WHAT #274 DID, AND THE TWO THINGS IT LEARNED THAT ARE NOT ABOUT WORDS.** It took the verb #227 left: ten identifiers to `invoiced`, 23 copy strings to `invoiced` or `charges`, four closed-vocabulary `key` values, and the prose across `app/`, `lib/`, `docs/` and `scripts/`. The copy ban gained the bare word and `BEATEN_BY_TABLE` gained `bill → Invoices`. **A CLOSED VOCABULARY IS INVISIBLE TO A VOCABULARY CHECK:** `copyStrings` skips a `key` property's value by structure and the identifier inventory visits Identifier nodes, so `billed-more`, `order-billed`, `billed-short` and `billed-over` were seen by neither matcher — what catches a new one is a value pin in the three offline files that assert a key by its literal, and the header now says so. **A FIXTURE THAT NAMES A FIELD AS AN INPUT KEY FAILS SILENTLY:** `offline/screen-briefs.mjs` held two literal status objects, and with two of their keys renamed under them the file passed 36 of 36 while every builder rendered `undefined` and one sentence dropped a whole term. Run before the fix rather than reasoned about. It is derived from `orderedItemStatus` now, so the producer names the keys.
- **WHAT #227 DID, AND THE THREE THINGS IT LEARNED THAT ARE NOT ABOUT WORDS.** It swept all four words from prose and identifiers: `arrival`/`arrived` and `shipment` off both, `bill` off every noun with the verb left standing, and `line` off the identifier family #228 had left behind. The ban list grew by `order lines?` and by a copy matcher for `arrival`, the check's scope grew to `docs/briefs/`, and two assertions were added — a complete identifier inventory with a reason per entry, and a cross-file pin on the two data shapes nobody declares. Three findings worth keeping. **A premise naming a file has to name the right file:** the citation that kept `order lines?` off the list was real but lived in `docs/notes/`, not in `lib/deliveryReconciliation.js` as the header claimed, and the scope boundary had been doing that work all along. **A shape can carry one figure under two names:** `orderedItemStatus` returned `deliveredBeyondOrder` and `arrivedBeyondOrder`, the same number twice, and only the rename made them collide — the `delivered` one had no reader at all. **A sweep must not touch a document about the words:** the ban-list literals, the planted violations, `BEATEN_BY_TABLE`'s keys and this file's own rule sentences all had to be restored after a blanket pass ate them, which is why the backticked bare word is the one form a sweep leaves alone.

**`line` NAMES A `Lines` ROW UNDER A JOB AND NOTHING ELSE — a `PO Items` row is an `ordered item`.** The base has one table whose rows are lines, `Lines`, reached as the `Line` link on `Purchase Requests`, and a word that already names a table cannot be spent on a second thing one level down: "this job's lines" and "this order's lines" are then two different sets and the sentence carrying either one no longer says which. `lib/deliveryStatus.js` settled this for #166's copy and stated it in that module's header; what it did not have until #269 was a statement anywhere a person naming something would look, which is why this was the rule that kept coming back — and it is now one instance of the paragraph above rather than a rule of its own. It comes back through the CODE — `orderedItemStatus` and the family in the table above say `line` for an ordered item, so anyone writing a comment or a doc beside them picks the word up from what is on the screen in front of them rather than from a convention they have not read. Recording the identifiers is therefore half the fix and this paragraph is the other half; the rename itself is #184's. The rule reaches prose, documentation and screen copy, and it is not retroactive on its own: a sweep of what is already written is its own change, and the count that would size one is in the pull request that added this paragraph.

**The `Qty` symmetry these must not break.** Every child row's own quantity is plain `Qty` (`PR Items`, `PO Items`, `Invoice Items`, `Delivery Items`); only an aggregate or a derived figure takes a modifier (`Invoiced Qty`, `Delivered Qty`, `Committed Qty`, `Signed Qty`, `Uninvoiced Qty`). Any rename has to keep that shape, which is why the audit's recommendations are all of the form `X Qty`.

**A checkbox takes a participle, not a noun.** It states a condition about the row, so: `President Signed`, `Paid`, `Used`, and `Over Delivered` since #181 — which was `Over Delivery` and read as though the column held an event. Hyphen-free per the field convention; the screen tag stays `Over-delivered` and the noun "an over-delivery" stays in prose, where it names the event rather than the flag. **This lived only on that one field's Airtable description until #181 moved it here**, which is the wrong place for a convention: a rule about how every checkbox on the base is named cannot be found by someone naming a different one.
