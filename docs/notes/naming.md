# Naming — the reasoning

Governs `lib/airtable/**` (with `airtable-access.md`), and any renaming of a field, a screen word or an identifier. **Read this before editing there** — CLAUDE.md carries only the rules that bind code outside this area; the derivation, the evidence and the alternatives weighed are here.

Moved verbatim out of CLAUDE.md — nothing in this file was rewritten. The migration was audited line by line and the result is in the pull request that created this file.

### Screen words and the fields behind them

**A screen word is not a field name, and this table exists so nobody searches the base for one and concludes it is missing.** Three relationships appear here and they are not the same kind of thing: a word that maps to one field, a word that deliberately differs from the field it reads, and a word that is no field at all. Where the relationship is not 1:1 the row says so rather than picking the closest field.

**A CODE IDENTIFIER that diverges on purpose belongs here too (#181), not only a screen word** — the last row is one, and the reason is the same: someone reads `resolveOriginalPOItem`, searches the base for "original", and finds nothing.

**A ROW LEFT THIS TABLE IN #274 AND THE DELETION IS THE FINDING.** It read `` `Billed` (invoice detail box) `` → `PO Items."Invoiced Qty"`, and its reason was that "on an invoice screen `Invoiced` would read as `this invoice`" — which made it the ONE recorded argument against spelling this act `invoiced`. **There is no such screen.** #232 scoped that figure to the invoice being read and deleted the `Ordered · Billed · Delivered` line with the caption under it; nothing in `app/` or `lib/` renders the word today. So the row was not a divergence to weigh, it was a divergence that had already gone, and #274 removed it rather than arguing with it. The distinction it was really about — one document's figure against the ordered item's total — is a `_shared.md` entry and stays there, where it is about two screens rather than two words.

**Divergences that are deliberate rather than drift**, recorded here because the audit that found them is now #181's and this table is where the reasoning belongs: `Amount` is a live formula on PR/Invoice Items and a static currency on PO Items (same meaning, frozen versus live); `Status` names five different value sets on five tables and is unambiguous within each; `Remark` is free text on PR Items and a discrepancy note on Invoice Items. None is a candidate for renaming.

**The rule #181 applied, so the next name has one to follow: a subtraction is named for what it subtracts.** `Outstanding` and `Remaining` were two words for one subtraction and one of them was also doing duty for a second, so three surfaces read as three quantities when there are two. Naming each for its subtrahend collapses them correctly — `uninvoiced` on `Materials` and on the PO detail (same subtraction, two scopes, one word, exactly as `Invoiced Qty` already spans both), `undelivered` on the delivery side. It also PINS THE NAME TO THE ARITHMETIC: if #20 changes `Materials."Uninvoiced Qty"` to subtract delivered quantity, the field has to be renamed in the same edit. That is the point rather than a cost, and it does not pre-empt #20's decision about what "outstanding" should mean — it frees the word by stopping a field from claiming it.

**A FILE NAME IS THE SAME DRIFT ONE LEVEL UP, and the test that kept #181 out of #184's way was "does the name make a claim the contents contradict".** Narrow is not the same as wrong. Two files failed it and were renamed. The old names are spelled here without backticks, because a later sweep for either string must leave this paragraph alone: app/components/DeliveryChips.js → `DeliveryStatusMarks.js`, because the marker beside the chips is documented at length as deliberately NOT one (`InferredMarker` then, `QualifierMarker` since #210 — see below); and scripts/tests/offline/guard-placement.mjs → `source-shape.mjs`, because its own exported `title` had already moved to `Call-site shape` and half of what it holds — `Quotations.File` has one writer, `Packing List File` has exactly two — is a writer count rather than a guard, in the category this file is named as the home of. Two were considered and left, with the reasons, because "rename it" is not the fix: `lib/materialsCache.js` describes two of its three writes (the third, `PO Items.Material`, is a link and not a cache), but whether that write belongs in a cache module at all is #184's question; and `lib/overagePR.js` also writes an invoice line and a delivery row, yet the whole correction hangs off that PR — it is even the field name on `Delivery Items` — so the name states the subject rather than one write.

**#210 RAN THAT SAME TEST ON AN EXPORT AND RENAMED IT: `InferredMarker` → `QualifierMarker`.** The component is a `!` in a circle whose whole meaning is the sentence handed to it, and it carried exactly one meaning while there was exactly one qualifier in the app. #210 removed the invoice axis's inference and put a MISMATCH label through the same component, while #167's overage attribution kept an `inferred` one — so the old name would have been false at one of its two call sites the moment it was reused. It is named for its shape now and the label says what it means, which is what `StatusChip` beside it already does. The test is #181's unchanged: does the name make a claim the contents contradict.

**THE RULE THAT DECIDES WHICH WORD WINS, STATED BECAUSE FOUR SWEEPS HAD TO FIND IT FOUR TIMES (#269).** `line`, `shipment`, `arrival`, `bill` — each was noticed the same way, by somebody reading a screen that said two things for one fact, long after the word had spread. Everything written down before this was the outcome of one of those: a list of words already found wrong, which cannot make a fifth word wrong until somebody adds it. **A concept with an Airtable table behind it takes that table's name, and nothing else may borrow the word.** `Deliveries` is a table, so a `Deliveries` row is a delivery and neither a delivery nor a delivery; `Invoices` is a table, so it is an invoice and not an invoice — the ground #235 stood on when it took a chip from `Billed` to `Invoiced`; `Lines` was a table, so `line` was spent — until #280 renamed it `Disciplines`, which is the one event that can retire a premise here and did (see below). CLAUDE.md carries the rule because that file is read at the start of every session and this one is read when the index points at it, and the whole failure this fixes is a word being picked up off the screen instead of out of a convention nobody opened.

- **THE TABLE NAME IS THE TIEBREAKER, NOT THE VOCABULARY, and confusing the two is the reading to guard against.** It settles which of two competing words owns a concept; it does not dictate the prose word for a row. `PO Items` is the table and `ordered item` is the word, because no table owns `ordered` or `item` and the screens chose one — so the table's own name appears in prose only as a backticked reference to the table or to a row of it. **Where no table owns the word, the chosen one is a row in the table above.** That is the layer, and it is what makes this a rule rather than a lookup: the table decides what a word may NOT be spent on, and the word-to-field table decides what it IS.
- **THE VERB SURVIVES ONLY WHERE NO VERB IS ALREADY SETTLED FOR THE SAME ACT (#227).** The clause below frees a verb from the table that owns its noun; this one says when that freedom is already spent. `arrive` does not keep it: #166 chose `delivered` for the same act, so `arrived` is not a free verb but a second one, which is the whole defect. The test is the reason the four words needed four different treatments rather than one, and it is what a fifth word should be held to first. **This bullet said `bill` kept it, on the ground that `Invoices` gives no verb and nothing else claims the act — and the second half was already false when it was written (#274).** `Invoiced Qty` and `Uninvoiced Items` claim it on the base, `uninvoicedQty` in `lib/poItemQty.js` claims it in code, and #235 moved a chip from `Billed` to `Invoiced`. Reading the test correctly therefore sends `bill` the way it sent `arrive`, and the mistake was not in the test but in looking only for another VERB: what settles an act is any derivation already built on the table's name, whether or not it is spelled as a verb.
- **WHICH LEAVES TWO FORMS AND NO THIRD (#274).** Where the act is a PARTICIPLE or a quantity it is `invoiced`, because that is what the base spells; where it is TRANSITIVE — an invoice doing something to an order, an ordered item or an item — it is `charges`. Neither is new: the first is `Invoiced Qty` and every chip on the invoicing axis, the second was already on a screen as `No invoice charges this order yet.` and pinned by `offline/screen-briefs.mjs`. **`invoices` as a transitive verb is barred**, and this is the rare vocabulary rule with a demonstration rather than an argument behind it: #227 rewrote `each bill ordered items` to `each invoice ordered items` and `both bill an ordered item` to `both invoice an ordered item`, and both garden-path into a noun phrase — they shipped and were read that way for two issues before #274 replaced them. **AND THE VERB IS ALL IT LEAVES (#303).** The clause above frees a verb from the table that owns its noun; nothing in it gives that verb the noun back. `charge` was the word for an `Invoice Items` row on five screen strings and about a hundred and ninety places of prose, on this file's own authority, and the authority was a misreading of #274 — see the paragraph below.

**THE ROW NOUN FOR EACH OF THE FOUR ITEM TABLES, AND THE ONE CONDITION FOR DROPPING THE MODIFIER (#303).** Four tables hold item rows — `PR Items`, `PO Items`, `Invoice Items`, `Delivery Items` — and a bare `item` names a row on all four, so a sentence naming two of them said one word for two tables. **A row takes its own table's name in the singular; the modifier drops where the string leaves no second kind of item row to confuse it with; a sentence naming two carries both.** `PO Items` is the standing exception to the first clause and not a new one: `ordered item` is that table's name with `PO` spelled out as what a purchase order does, which is the divergence the bullet above already records. The second clause has two applications and one test — *does this string offer the reader a second kind of item row?* A sentence answers for itself. A LABEL WITH NO SENTENCE AROUND IT — a heading, a column head, a button — takes its screen's own subject, which is why `Items` / `Item` / `+ Add item` stand unmodified on `/prs/[prId]`, `/prs/new`, `/pos/[poId]`, `/invoices/new` and both invoice screens, all five of which head the section over their own rows and their neighbours over documents.
