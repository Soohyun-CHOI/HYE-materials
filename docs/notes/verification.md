# Verification — the reasoning

Governs `scripts/**`. **Read this before editing there** — CLAUDE.md carries only the rules that bind code outside this area; the derivation, the evidence and the alternatives weighed are here.

Moved verbatim out of CLAUDE.md — nothing in this file was rewritten. The migration was audited line by line and the result is in the pull request that created this file.

### Verification tiers (#152)

Checks are split by **cost of execution**, not by issue. A cheap check welded into a script that writes to the shared base costs credentials and fixtures to reach, so it does not get run — and a check nobody runs is not a check. #152 is the precedent: six assertions sat invalidated for weeks, in two scripts reporting `SOME CHECKS FAILED` at exit 0.

**AND IT HAPPENED AGAIN IN THE TIER THAT STAYED, WHICH IS THE THING TO NOTICE (#356).** `verify-materials-cache-18.mjs` asserted that `getItemsByPO` omits `invoicedQty`, on #132's rule that invoice data stays off the employee path. **#235 retired that rule and said so in a paragraph on the field itself** — putting `Invoiced Qty` on `recordToPOItem` on #211's ground that what a vendor invoiced is readable by anyone who may read the order behind it. The check went on contradicting the code for eleven issues, because the only thing that reads it is a 219-operation run somebody has to have a reason to start. #152's remedy does not reach this: the assertion is not cheap-tier material — it is about a live projection off a live record. **What the split actually buys, restated honestly, is that the offline tier cannot rot unnoticed; the credentialed tier still can, and a stale assertion there is found by whoever next has a reason to run the script.** The one cheap mitigation is the exit code: this script returns 1, so the staleness is loud the moment anyone does.

- **`scripts/tests/offline/` — the standing tier.** Plain `node`, no env vars, no Airtable, no Blob, no dev server, no module loader, creates nothing. `npm test` runs all of it; `.github/workflows/checks.yml` runs `npm test` on every push and PR.
- **`offline-checks` is a required status check on `main`**, so this tier passing is a merge condition rather than advice. The name is the **job key** in `.github/workflows/checks.yml` — renaming that job renames the check GitHub reports, while the branch protection rule keeps waiting for the old name, and a PR then sits permanently "Expected — waiting for status to be reported" with nothing failing and no obvious cause. If the job is ever renamed, update the required-check setting in the same change. Each file exports `title` and `run({ check, log, assert })` and also runs standalone (`node scripts/tests/offline/source-shape.mjs`). The runner **scans** the directory rather than listing files, so a new check is in CI automatically — same reasoning as #147's enumerated inventory: anything that has to be registered somewhere can be forgotten. Files beginning with `_` are shared helpers (`_harness.mjs`, `_ast.mjs`). `fixture-cleanup.mjs` (#171) is the newest check: it walks every `verify-*.mjs` on the AST and requires each one that creates records to go through the fixture helper, with no `Promise.allSettled` whose results are discarded, no empty `catch`, and no `process.exit` above its cleanup call. **It carries no exemption list on purpose** — a script that cannot use the helper is evidence the helper is wrong, not a line to add. `product-name.mjs` (#201) is the second check with none, and it gets there a different way: it scopes itself to `app/` + `lib/` so that every legitimate spelling of a superseded name is outside it rather than excused within it. `us-english.mjs` (#215) is the third, by the same move and for the same reason — a British spelling has one legitimate use, being cited as the form not to write, and every site that cites one is documentation. Its cost is stated in its header rather than hidden: 69 of #215's 114 fixes were outside that scope, so CLAUDE.md, `docs/notes/` and `scripts/` are swept but not guarded.
- **`source-bytes.mjs` (#231) IS THE FOURTH WITH NO EXEMPTION LIST, AND #195 SWAPPED HOW IT GETS THERE — A PROPERTY INSTEAD OF A SCOPE.** It fails a tracked file carrying a NUL byte, which is what removes a file from a repository-wide search silently. #231 kept its exemption list empty by scoping to `.js`/`.jsx`/`.mjs`/`.md`/`.py` under four directories, so binary assets were excluded by not being those. **That was true and it was not free: 24 of 415 tracked files sat outside it**, and not all were assets — `CLAUDE.md` is at the repo ROOT so the file every session loads first was never scanned, `.github/workflows/checks.yml` defines CI, and `components/ConfirmDialog.js` is live source in a directory the walk simply did not list. The subject is every tracked file now, and what replaces the extension list has no list and no threshold in it: a NUL-bearing file is TEXT if it carries a UTF-16/UTF-32 BOM or decodes as strict UTF-8, and a genuine binary otherwise. A NUL is a valid UTF-8 code point, which is what makes the second clause work — source that went binary by accident still decodes, while a real `.ico` or `.ttf` is full of sequences that are not valid UTF-8. **Git's own verdict was the non-obvious alternative and it does not work**, measured rather than assumed (see `airtable-access.md`). The false-positive direction is in its header: a binary whose bytes happen to be valid UTF-8 reads as text, which costs a look, where the reverse is a file silently outside every sweep.
  - **THE WIDENING COST IT THE FREE HALF OF ITS ANTI-VACUITY, WHICH IS THE PART WORTH COPYING.** While the scope excluded binaries, "no file holds a NUL" needed only a planted byte and a walk that reached files. With a discriminator in the way there is a second thing to prove — that a genuine binary PASSES — or the check is the old absolute wearing a costume and nobody would know. So the bytes of an `.ico` and a `.ttf` are written beside the claim and required to classify as binary, alongside the two accidents required to classify as text. Synthetic buffers rather than fixtures on disk: nothing to clean up, and the bytes sit next to the assertion about them.
  - **IT IS ALSO THE FIRST CHECK IN THIS TIER TO RUN A SUBPROCESS, and the reason is the thing it is checking.** Its file list is `git ls-files` rather than a walk, because its subject is precisely "the files the repository has" and any walk written here would be a SECOND answer to that, with its own ignore rules and its own drift — which is #187's defect one level up, where `npx eslint .` linted two vendored files under a gitignored `.venv` because a flat config does not read `.gitignore`. Its own former walk had that shape and the 24 files are what it cost. The tier boundary is untouched: `git ls-files` needs no credentials, no network and no variable, and an empty answer is caught by the anti-vacuity assertions rather than read as a clean tree.
- **`scripts/tests/verify-*.mjs` — the credentialed tier.** Needs `.env.local` and the loader, writes throwaway fixtures to the shared base, and some need `npm run dev`. Human-initiated on purpose and deliberately not in CI: one shared base means concurrent workflow runs would create and delete records against each other. These no longer contain their offline parts — run `npm test` for those.
- **Where a new check goes:** if it needs no credentials it goes in `offline/`, otherwise it goes in the credentialed tier. The boundary is not a judgment call — `lib/airtable/client.js` throws `Missing AIRTABLE_API_KEY` at module load, so importing it, or anything that imports it, puts a check in the credentialed tier. Offline-safe today: `lib/prVisibility.js`, `lib/authzWrap.js`, `lib/units.js`, `lib/editLogFields.js`, `lib/variance.js`, `lib/prSigning.js`, `lib/itemNaming.js`, `lib/poItemQty.js`, `lib/airtableFormula.js`, `lib/materialPriceView.js`, `lib/deliveryAccess.js`, `lib/deliveryAllocation.js`, `lib/idSequence.js`, `lib/deliveryStatus.js`, `lib/overage.js`, `lib/invoiceItemFold.js`, `lib/productName.js`, `lib/authTokenState.js`, `lib/airtableOps.js` (#190 — importable under plain `node` because `node:async_hooks` is a built-in; it is nonetheless server-only, and for the browser it is a forbidden root, which is a different boundary from this one), `lib/poListView.js`, `lib/fileSource.js` (#438 — `isOurBlobUrl` left `lib/blobIngest.js` for it, and it takes the environment as an argument so a check never sets a process variable). **An offline-safe module must have no UNRESOLVABLE imports, which is stricter than "pure" (#19):** the tier runs under plain `node` with no loader, and node cannot resolve the extensionless intra-lib imports the rest of the app leaves to Next. So an offline-safe module either imports nothing, or spells the extension out: `lib/materialPriceView.js` imports `"./itemNaming.js"` that way, because the alternative was inlining #18's naming rule — a second implementation, which is worse than deviating from an import style. `lib/deliveryAllocation.js` is the second such case (#162), importing `"./materialPriceView.js"` for `countsAsOrdered` rather than re-typing `committedQty > 0`. **That friction is resolved as of #169**, the third consumer and therefore the condition above firing. `countsAsOrdered` now lives in `lib/poItemQty.js` (per-item quantity judgments, dependency-free) and both `lib/deliveryAllocation.js` and `lib/deliveryStatus.js` import it from there. The condition was only ever written HERE — neither module carried it — so a reader of either file had no way to know the move was pending. Leaving it would have made a delivery-STATUS module import a material-price-VIEW one. Not: `lib/poWithdraw.js`, `lib/blobIngest.js`, `lib/ids.js`, `lib/materialsCache.js`, `lib/deliveryCandidates.js`, `lib/deliveryReconciliation.js`, `lib/overagePR.js`. #18 is the worked example of one concern splitting across both tiers rather than picking a side: the two Unit lists are files, so comparing them is offline (`offline/unit-options.mjs`); what the Airtable fields actually hold needs the Metadata API, so that is credentialed (`verify-unit-options-18.mjs`). Neither subsumes the other — a hand-added option passes the first and fails the second.
- **Exit codes are mandatory for anything that computes a verdict**, in the shape #147 set: **0** all clear, **1** something failed, **2** no failures but a part could not run. A script that prints its verdict and returns 0 regardless makes a failure indistinguishable from a pass to anything but a reader. **A LEAK IS 1, NOT 2 (#171)** — a run that left rows on a shared base needs a hand, which is the same criterion that made 1 right for a failure, while 2 means a part could not run and needs none. Two meanings for 2 would demand two different human responses. Every script that creates records therefore carries two verdicts and two sentences: `pass` about the feature, and `fixtures.describe()` about the run's effect on the base. **This named `verify-variance-15.mjs` as the file that computes no verdict about its subject, and #283 made that false** — that issue added an assertion about the `Calculated Total` formula, a rule living on the Airtable side, and a failure there needs a hand rather than a reader's judgment. So its 1 means a leak OR a failed assertion, which is this bullet's own contract, and the script's own header was amended to say so while this line was not. Corrected per #181 by #172, which had to classify every script in the tier and read it. **The shape it described is real and belongs to `verify-unread-fields-182.mjs` now**: that one exits 1 when it finds a field with no reader, and prints in the same breath that each line is a question for somebody with the base open rather than a verdict, because the Metadata API cannot show it a view's filter. `verify-detect-po-92.mjs` remains the one file with no exit code at all, and it creates nothing.
- **EVERY SCRIPT IN THIS TIER OPENS WITH ITS PROVENANCE, FROM `scripts/tests/_provenance.mjs` (#172).** A run prints findings and nothing about the tree it ran against, so a result kept in a terminal or pasted into a pull request cannot be tied to a commit afterwards — and establishing what a past run covered then means running it again at hundreds of operations. The header carries the commit, the branch and the dirty entries. **It is a THIRD shared module rather than a widening of either existing one**, and the deciding case is already in the tree: `verify-edit-log-fields-181.mjs` had written its own header while importing neither `_fixtures.mjs` nor `_liveApp.mjs`, so provenance demonstrably has to be reachable without them. The subjects also divide cleanly — `_fixtures.mjs` owns what a run did to the BASE, `_liveApp.mjs` owns reaching the running APP, and this owns which CODE ran. Widening either would have made one module carry two.
  - **SEVEN COPIES HAD DIVERGED THREE WAYS, WHICH IS WHY THE SHARED ONE KEEPS A COUNT AND NO BOOLEAN.** Four returned `{ dirty: boolean, dirtyCount: number }`, two returned `{ dirty: number }`, and `verify-deliveries-162.mjs` held the first while rendering `${git.dirty && git.dirtyCount}` — right only because `true && 3` is 3. A field derived from another field is a second thing to keep in step, and that is the gap the nonsense expression grew in.
  - **`N uncommitted file(s)` WAS FALSE IN ALL SEVEN, AND THE CORRECTION IS WHAT THE HEADER NOW PRINTS.** `git status` reports one entry for an untracked DIRECTORY rather than one per file inside it: measured, three new files under one new directory alongside two other changes reported as four entries, which every copy announced as "4 uncommitted file(s)". The collapse is git's and does not change, so the reading does — the count is of ENTRIES, the entries are listed rather than summarized (capped, then counted), and an untracked directory says on its own line that it stands for contents git did not enumerate. Walking it to recover a file count is deliberately refused: that is a second answer to a question git already answered, with its own ignore rules to drift.
  - **DIRTY IS `--porcelain` AS IT COMES, AND `--ignored` WOULD DESTROY THE SIGNAL RATHER THAN SHARPEN IT.** Tracked modifications and untracked non-ignored files both belong, because a new module under `lib/` or a new script here changes what ran and the commit does not name it. Ignored files must stay out for a measured reason: this tier cannot run at all without `.env.local`, which is gitignored, so counting ignored files would mark **every** credentialed run dirty. The same exclusion is what stops a run being called dirty for writing its own `.airtable-ops.jsonl` ledger or for `commit-msg.txt` and `pr-body.md` sitting beside it. On a clean checkout `git status --porcelain` returns zero lines while fourteen ignored entries sit at the root.
  - **WITH NO GIT IT PRINTS UNKNOWN IN CAPITALS AND CARRIES ON.** Throwing would let a missing `git` stop a run that has nothing to do with git; printing nothing would let a run with no provenance look exactly like one with good provenance. The exit code is untouched either way — the header is provenance and never a verdict, which is also why the two scripts that judge nothing carry it.
  - **`offline/run-provenance.mjs` holds it, and walks the directory rather than listing it** — a hard-coded inventory cannot see the script nobody remembered, which is this check's whole subject. It asks that each `verify-*.mjs` imports the helper and calls it, on the AST so prose naming the function satisfies nothing. **What it cannot ask is that the call comes first**, since this tier never executes a credentialed script; a call buried after a hundred lines of output would pass. Its three-line walk is duplicated from `fixture-cleanup.mjs` and deliberately not extracted — `_entrypoints.mjs` was worth pulling out because it carried a mechanism two checks had to agree on, and this is `readdirSync` plus a prefix test.
- **THE FIXTURE HELPER DELETES TEN TO A REQUEST AND FALLS BACK TO ONE AT A TIME (#191).** `_fixtures.mjs` issued one request per row; `verify-overage-167.mjs` removed **64 rows in 64 requests**, measured rather than estimated. It groups by table and batches now: the same run is **14 requests**, and `verify-materials-cache-18.mjs` went **34 to 9**. Both runs' residue read 0 before and after, and both deleted the identical set of rows.
  - **THE FAILURE SHAPE WAS MEASURED BEFORE THE DESIGN, AND IT INVERTED THE ISSUE'S ASSUMPTION.** #191 was written expecting batching to cost per-record reporting, which is what #171 bought. Against the live base: a batch carrying an id that no longer resolves answers **404 NOT_FOUND** and NAMES one — `Could not find a record with ID "recX"` — while the single-record form answers **403 INVALID_PERMISSIONS_OR_MODEL_NOT_FOUND**, the sentence `residueState` already documents as indistinguishable from a dead credential. **So the batch form diagnoses better than the form it replaces.** A malformed id is a third answer, 422 `INVALID_RECORDS`.
  - **AND IT IS ALL-OR-NOTHING, WHICH IS WHAT MAKES THE FALLBACK THE WHOLE BATCH.** Established by mixing one already-deleted id into a batch of three and reading the other two back: both still present. A failed batch therefore has no successes to preserve, and the id it names is only one of however many are bad — peeling them off one at a time is unbounded where re-sending the batch as singles is exactly N. The retry sends `destroy([id])` rather than `destroy(id)`, one id in the batch form, because that is the shape whose refusal names the record.
  - **WHAT THE GROUPING COSTS, SINCE THE ISSUE BODY COUNTED IT WITHOUT.** A request carries one table's ids and every child must go before its parent, so rows are grouped by TABLE rather than packed ten at a time across a run. 64 rows over 13 tables with no table holding more than 8 is **13 requests, not the 7** a table-blind packing would give — the ceiling of ten never fires there at all. The measured 14 is 13 plus one: `Invoice Items` is flushed twice, once as its own bucket and once as a child of `Invoices`, which is two phases rather than a miss.
  - **THE CREATION SIDE IS THE SAME SIZE AND IS DELIBERATELY UNTOUCHED.** That run creates **64 rows in 64 requests** too. Batching them is a change to the production functions the fixtures are built through rather than to the harness, which is a different judgment; the figure is recorded here as its input. The delete loop's remaining per-record read — one `find` per parent that has children, 20 of them in that run — is left alone for a narrower reason: `findByRecordIds` throws on an id that does not resolve, and a parent legitimately gone is exactly the case cleanup has to survive.
- **An operation count is how a "does not read per record" rule gets checked (#193), and source shape cannot do it** — a per-child loop wrapped in a helper reads as batched on the AST, which is the same weakness this file records for every structural check. `verify-batched-reads-193.mjs` Part E calls the production reader on a 3-child parent and an 8-child parent and requires the SAME figure, plus a third clause the equality alone does not buy: the 8-child call must come in under `1 + 8`, which every one-at-a-time shape exceeds no matter how it is wrapped. #244's `getOpenPOs` bound is the same move a level up. **Its anti-vacuity is that "equal" is also what two zeros are**, so the child counts must differ and be non-zero and the cost must be above zero — three clauses for one claim.
- **`findChildRecords`' ordering and short-result rules are pure judgments the offline tier cannot reach**, because they live in `lib/airtable/client.js`, which throws without credentials. Extracting five lines into a module of their own to make them offline-testable would trade a real boundary — the one that defines this tier — for a testable one, so they are proved in `verify-batched-reads-193.mjs` Part F instead: a reversed id list comes back reversed, an unresolvable id throws and names itself, and an empty link array costs zero operations.
- **`_entrypoints.mjs` is the one enumeration of what an entry point is (#224)**, shared by `authz-structure.mjs`, which asks whether each endpoint export is gated, and `airtable-ops.mjs`, which asks whether each entry point opens an ops-label scope. The two disagree on scope — a page carries its authorization in its own body rather than in a wrapper, so authz has never inventoried pages, while ops must cover every one — and on verdicts; what they share is the mechanical part, which written twice would be two lists to keep in step, with a silent failure mode: a surface one of them stops seeing stops being checked. **The extraction was proved pure by diffing `authz-structure.mjs`'s WHOLE OUTPUT across it**, all 40 lines including every per-entry line and `inventory: 34 endpoint exports across 19 files` — a count and an exemption tally are what a missed export would move, so an identical dump is the evidence.
- **`routeTemplate` HAS FOUR READERS AND A ROUTE GROUP IS INVISIBLE IN A URL (#348).** It derives a route from a file's path, and until the tools axis needed a shared layout over three collections there was no parenthesized directory in the tree — so stripping the `app` prefix was the whole derivation. It strips `(group)` segments now, and the four are worth naming because each wants something different: `airtable-ops.mjs` compares the derived route against the ops label a page opens its scope with; `screen-briefs.mjs` turns it into a brief's FILENAME; `url-parameters.mjs` attributes a URL parameter to it; and `scripts/screen-strings.mjs` needs the INVERSE, a route back to the directory its page lives in. **Only the fourth broke, and silently** — it rebuilt the directory as `"app" + route`, which pointed at a path that does not exist, and a screen with no files reports no strings, which is a legitimate answer. It maps back through the page files now, so the two directions are derived from one list and cannot disagree. The general shape: a derivation with an inverse needs the inverse derived too, not reconstructed.
- **An anti-vacuity assertion that shares the predicate it is checking is not one, and #224 measured that on its own first attempt.** `airtable-ops.mjs` compares the enumeration's page count against an independent count of `page.js` files, precisely because the per-entry assertions all ask whether what was FOUND carries a label — an enumeration silently finding 18 of 21 pages passes every one of them, and "the count is above zero" passes too. The first version of that independent count called the same `isPageFile` predicate, so narrowing `isPageFile` to skip `app/admin/` moved both numbers together: entry points fell from 55 to 52, three admin pages went unexamined, and the run stayed green. It counts by FILE NAME now, and the mutation fails it. **The general rule: a second path to the same number has to be a second path.**

- **`offline/unread-exports.mjs` IS THE FIFTH WITH NO EXEMPTION LIST, AND IT GOT THERE BY RESOLVING ITS FINDINGS RATHER THAN BY SCOPE OR BY A PROPERTY (#182).** It fails an export under `lib/` that nothing outside its own file imports, walking the import graph in `client-import-safety.mjs`'s shape. All twenty of that issue's findings lost the `export` keyword or went entirely, so there was nothing to excuse — and an EMPTY list was written and then deleted, on `fixture-cleanup.mjs`'s own ground: an export that cannot lose the keyword is evidence this rule is wrong, not a line to add, and an empty list is a place to put that evidence instead of acting on it. If a real exception ever appears the list is written then, against a case.
  - **THE CORPUS IS WIDER THAN THE SUBJECT AND THAT IS THE EASY HALF TO GET WRONG.** The subject is `lib/**`; the importers are `app/`, `lib/`, `scripts/`, `components/` **and the repo-root files**, which a walk of those four directories misses — `proxy.js` is live source at the root. Two tiers are readers and neither is a finding: 38 exports are imported only by `scripts/tests/offline/`, and a check pinning a constant BY VALUE is exactly the reader this repository's documentation style rests on.
  - **AND IT DOES NOT REACH #217's THIRD SHAPE, WHICH WAS MEASURED RATHER THAN ASSUMED.** A property of a returned object that nothing reads is a different question, and a name-keyed detector for it was built, run and left out: it found six real ones, and it is unsound in the direction that matters — `recordToMaterial.committedQty` has no reader of a Material and still reads as live, because `recordToPOItem.committedQty` shares the name. Separating them is type or dataflow analysis. #217's own shape is narrower again — a field its only consumer OVERRIDES, so the name IS read — and no import graph or name census can see it at all. Both stay review matters, and the check's header says so, because the place somebody asks "is this covered" is the check that covers the neighbouring case. The six were resolved by hand in #182: three deleted, three kept with a reason each.
  - **THE BASE HALF IS A SEPARATE SCRIPT BECAUSE IT NEEDS CREDENTIALS.** `verify-unread-fields-182.mjs` is one Metadata read, no record operations, creates nothing — the cheapest script in that tier and meant to be re-run whenever a schema change lands. A field's readers are exact rather than text-matched: Airtable hands every formula and rollup its `options.referencedFieldIds`, which is why it does not care that of 18 formula fields the API renders 12 by id and 6 by name. **What it cannot ask is the view**: the Metadata API returns id/name/type per view and NO filter configuration, so a field read only by a view filter, an automation or an interface reads as unread — and the script prints its findings as questions for somebody with the base open rather than as a verdict. It reported none on 299 fields.
- **A NEW OFFLINE CHECK NEEDS AN ANTI-VACUITY ASSERTION IN THE SAME FILE** — something that proves the check can see what it is looking for. "X is absent" and "the traversal found nothing" are the same result, and a check that cannot fail is worse than no check because it reads as coverage. **This was CLAUDE.md's until #334, and the audience test is what moved it**: you cannot need this rule without editing `scripts/tests/offline/`, and the index makes this file required reading before you do — so the reader is reached, one mandatory hop away. The rule it was routed away from is the one beside it there, that this tier cannot see RENDERING, whose reader is someone shipping a SCREEN and may never open `scripts/` at all. Frequency was not the test; reachability was. If it turns out to be skipped in practice the answer is a meta-check that enforces it, not a second copy in CLAUDE.md — one rule written twice is the duplication that file's own "One rule, one implementation" section is about.
- **A CHECK THAT VERIFIES AN ENCODER NEEDS A DIFFERENT LIBRARY TO DECODE IT (#351), AND THAT IS WHAT THE THIRD DEVDEPENDENCY IS FOR.** `offline/tool-label-qr.mjs` encodes a tool label's address with `qrcode` and decodes it with `jsqr`, which is a devDependency on the same footing as `acorn`: reachable only from this tier, installed by `npm ci`, and load-bearing for one claim. An encoder decoding its own output establishes that it is self-consistent and nothing else — the symbol could be internally coherent and not a QR code — so the decoder reads the format information, corrects with its own implementation, and reports the version and the mode for comparison against the encoder's answers. **The tier boundary is untouched by this**: neither package reaches `lib/airtable/`, so a bare specifier resolving under plain `node` is all it costs. **What the round trip does NOT reach is the rendering** — it decodes the matrix, not the SVG bytes the route serves, and whether a browser paints them decodably is exactly what this tier never does; that half is a browser measurement recorded in the pull request.
- **AND THAT CHECK IS ALSO THIS TIER'S CLEANEST WORKED EXAMPLE OF #224's RULE, BECAUSE IT FAILED IT FIRST.** Every quiet-zone assertion in it was written against `QR_QUIET_ZONE_MODULES` — the constant, the derived side, the SVG's own margin and the builder's report — so changing 4 to 2 moved all four together and **all 47 assertions passed**. Measured by mutation before the fix, not reasoned about. Three literals replaced the relations, and the mutation now fails five. The rule is the same one the `isPageFile` incident produced: a second path to the same number has to be a second path, and an assertion comparing a value against an expression over that same value is not one however many terms it has.
- **A PHYSICAL DIMENSION IS THIS TIER'S EASIEST CLAIM TO FAKE, AND #353 IS THE WORKED EXAMPLE OF NOT FAKING IT.** Everything a printed sheet needs is pure arithmetic reachable from one constant, so an assertion written in terms of that constant holds for any value it takes — including a stock too small to carry a scannable symbol. `offline/tool-label-sheet.mjs` types the figures out as literals instead, so changing stock changes them in the same commit; and it adds the stock's published margins and pitches back up to the page size, which is a second path that a mistyped figure fails. Two further things it does that a dimension check should: it holds the derived module size above a floor, so an unprintable stock is a failing check rather than a discovery on paper; and it adds one label's parts up, because **if the pieces do not fit inside one label no layout can stop them overlapping** — the one physical claim a tier that never renders can actually hold. **The list of what it cannot see is longer than usual and is in its own header**, which is the right place for it: a label overlapping its neighbor, ink inside the quiet zone, a browser's print scaling, and whether `@media print` hid anything.
- **AND ITS FIRST VERSION FAILED ON ITS OWN ARITHMETIC, WHICH IS WORTH KEEPING.** The stock's figures are exact inch conversions — 3/16 of an inch is 4.7625 mm, 1/8 is 3.175 — and rounding them to hundredths destroys both, so two assertions disagreed with the numbers they were checking. Rounding to four decimals fixed it. A check being wrong that way round is the cheap direction; the expensive one is the mutation-passes shape the bullet above is about.
- **`@napi-rs/canvas` IS THE FOURTH DEVDEPENDENCY, AND IT IS WHAT LETS THIS TIER LOOK AT A DRAWN PAGE (#40).** `offline/po-quotations.mjs` renders the order document with PDF.js and reads pixels, because its claim is which way up a photograph is drawn, and only a rendering can be held against a measurement — comparing the transform matrices would compare the idea with a second copy of itself. That is #351's rule one step on: pdf-lib writes, PDF.js reads and draws, and a table measured in Chromium says what should be where. PDF.js draws into a canvas in Node through this package, which `pdf-parse` already pins at 0.1.80, so declaring it adds no copy to the tree; it names what the check would otherwise have reached by accident, and it is also what makes the check's fixtures real JPEGs and PNGs rather than headers that draw as nothing. **It is the first native module this tier loads.** The lockfile carries its prebuilt binaries for Linux, macOS and Windows, so `npm ci` in CI installs the right one; a platform with none fails that one file at load, and `run-all.mjs` names the file rather than losing the rest.
- **Source-shape checks belong in `offline/source-shape.mjs`**, together, on the AST.   - **THE ASSERTION IS ABOUT THE CALL, NOT THE ARGUMENT, and the obvious rule is the wrong one.** "Every `createItem` passes a category" would forbid the one row `docs/briefs/prs-new.md` says the request form has to be able to show — a Draft item saved before the catalog existed, which opens with nothing picked — and buying it back needs the exemption list this tier refuses. So the helper holds the count of deliberate exceptions (`allowMissing`, with a `why`), `allowMissing: 0` reads as a claim rather than a waiver, and the check only asks that the seed says something. `createItem` itself cannot refuse: a Draft saves half-picked (#72), so the service layer has no way to tell that row from a caller that forgot. That is why the refusal lives in three places that can — the submit action, the seed helper, and the check.
  - **ONE LEVEL-1 BRANCH PER SEED, WHICH REPLACED A MARKER ON EVERY SCREEN.** Scenarios must not share a material — allocation matches candidates on the `Material` link (#18) — and identity is `Category` + `Size` + `Unit` after #356. The `NNN-DEMO ` name prefix used to keep seeds apart and put its marker in front of anyone reading the demo; a branch each keeps them apart and puts nothing on screen. The check asserts the slices are disjoint and that every one of the 83 codes is in the committed CSV, so a typo fails in CI rather than several hundred operations into a run.
- **`offline/wipe-coverage.mjs` ASKS THE QUESTION `wipe_base.mjs` WAS ALREADY ASKING AND NOBODY HEARD (#358).** That script refuses to run when a table is in `TABLES` but in neither its delete order nor its keep lists — a guard from #162, when two tables arrived at once. It was right and it fired: from #334, which added three tools tables, `wipe_base.mjs` exited 1 without deleting anything, and **for twenty-odd issues nobody noticed, because the only way to hear a guard inside a script is to run the script, and this one is run about twice a year.** The commit that adds a table now fails in CI until its author says what a wipe should do with it. What the check cannot ask is whether the answer is right — a table at the wrong depth passes — which is why `wipe_base.mjs` carries its ORDER comments and, since #358, two separate keep lists: `KEPT` for a table kept for its own sake, `KEPT_FOR_THEIR_LINKS` for one kept because something else points into it.
  - **ADDING COVERAGE TO A SEED DOES NOT COVER AN ALREADY-SEEDED BASE, and that is worth saying because it is easy to assume otherwise.** Every seed here is skip-if-exists, so a field a seed learns to populate appears only from the next CLEAN seed onward — measured on #181's own change: the run exited at "Already seeded", printed its guide, and created nothing, so `Deliveries."Packing List PO"` is carried by no stored record on this base even though the seed now writes one. The two ways out both cost something a reader should weigh rather than have chosen for them: deleting the seed's own Materials rows re-seeds cleanly but leaves the previous generation of orders, deliveries and invoices standing beside the new one, and setting the field by hand on the record the seed would have set it on is truthful (allocation already happened; the value is that delivery's own single order) but is a hand edit to stored demo data. **A seed change is therefore a claim about future coverage, not a verification of the present one.**
  - **Each of these prints a WHERE TO LOOK guide, and the guide is part of the script's job rather than decoration** — #166's own copy defect ("nothing delivered yet" on an invoice where 10 of 13 had been delivered) was caught by reading a seeded row, not by a check. Which is also why `seed_delivery_status_166.mjs`'s skip path had to be fixed to reach that guide at all: `printGuide` is a hoisted function declaration but `ids` was a `const` below it, so a re-run — the only way to reach the skip path — died in the temporal dead zone before printing anything. The guide's `?? "A"` placeholders exist for exactly that path, where the scenarios are on the base but their ids are not in hand.
  - **`seed_material_prices.mjs` generates every PO before backdating any of them, and that order stopped being load-bearing in #164.** `lib/ids.js` used to number a PO by counting the POs whose `Created Date` is today, so backdating one inside the creation loop hid it from the next call's count — the first version of the script did exactly that and produced **five POs sharing one PO ID**, which makes `/pos/[poId]` ambiguous. The counter now counts the ID prefix and reads no date field, so that failure is unreachable; the generate-then-backdate order and the script's assertion that the IDs are distinct both stay, because they cost nothing and the assertion is what would catch a regression. This is the incident #164 cites as evidence that a counter reading an app-written date field is only conditionally correct, and it is reproduced against the live base in `verify-invoice-ids-164.mjs` Part D.
  - **`seed_over_delivery_165.mjs` builds its orders through the real approve-and-generate flow for one specific reason**, not just realism: PO generation is what writes each ordered item's `Material` link (#18), and allocation matches candidates on that link and never on `Item Name` text. It backdates the four `Created Date`s afterwards so "oldest first" and "most recent" are visible rather than decided by a same-day `PO ID` tie-break, and it fills two of the orders through the production `planDelivery` so the fully-delivered branch has real rows behind it.
